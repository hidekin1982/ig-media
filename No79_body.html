保存のところだけ失敗する。原因は書き方のほうだった

絵は作れているのに、最後の1行だけが失敗する。しかもエラー文には「一般的なエラーが発生しました」としか書いていません。

何が一般的なのか、こちらが知りたい。

原因は、保存先の書き方でした。

  • 相対パス（.\out.png のような書き方）で渡していた
  • 実行したときの現在地が、自分の思っている場所と違っていた

直し方は1つです。保存先は必ず、頭からの絶対パスで渡す。

上の型で $HOME\Desktop\header.png と書いてあるのは、そのためです。$HOME は自分のユーザーフォルダに置き換わるので、どこで実行しても同じ場所に出ます。

フォルダを自分で指定するなら、そこが存在しているかも見てください。無い場所には保存できません。

New-Item -ItemType Directory -Path "C:\midashi" -Force

この1行を足しておけば、無ければ作り、あればそのまま通ります。

1行に何文字入るか。改行は手で決める

自動で折り返させると、変な場所で切れます。

「見出し画像を1枚ずつ」の途中で行が変わると、読む人はそこで一度つまずく。だから折り返しは自動に任せず、$Title の中にある改行の印を自分で動かします。

  • 72px：全角17文字まで

言葉の切れ目で割る。

「見出し画像を／1枚ずつ作らない」は意味の切れ目で割っているので読めますが、「見出し画像を1枚／ずつ作らない」だと読めません。同じ文字数でも、割る場所を1文字動かすだけで読みやすさが変わります。

字を小さくする前に、まず割る場所を疑ってください。

色は3つでいい。書き換えるのはこの行

色の指定は、型の中の3行だけです。

  • $g.Clear(...) が背景の色
  • $fg が文字の色
  • $ac が差し色（左の帯と、サブの前の四角）

数字は赤・緑・青の順で、それぞれ0〜255です。

決め方はこうしました。

  • 背景は暗い色（一覧に並んだとき、白い画面の上で浮く）
  • 文字は真っ白より、少し黄みを入れる
  • 差し色は1色だけ。2色使うと素人っぽくなる

私は背景を墨色、差し色をオレンジに固定して、以来そこを触っていません。決めることを減らすのが目的なので、この配色そのものが正解かどうかは、正直あまり関係がありませんでした。

3色決めて、二度と触らない。

1枚ずつ動かすのをやめる。一覧から全部出す版

ここからが本題です。

1枚ずつ書き換えて実行するのでも動きますが、10枚を超えたあたりで面倒になったので、私は途中から表を先に作って、そこからまとめて出す形にしました。

まず、こういう表を作ります。名前を midashi.csv にして保存してください。

name,title,sub
No01,見出し画像を|1枚ずつ作らない,テンプレ1本で、全部そろえる
No02,型を決めると|そろう,書き換えるのは3行だけ
No03,数えて|終わらせる,出す前の確認は1分

| が改行の位置です。次に、これを読んで全部出す側。

Add-Type -AssemblyName System.Drawing

$List = "$HOME\Desktop\midashi.csv"
$Dir  = "$HOME\Desktop\midashi"
New-Item -ItemType Directory -Path $Dir -Force | Out-Null

function New-Header($Title, $Sub, $Out) {
    $W = 1280; $H = 670; $FAM = "Yu Gothic UI"
    $bmp = New-Object Drawing.Bitmap($W, $H)
    $g = [Drawing.Graphics]::FromImage($bmp)
    $g.TextRenderingHint = 'AntiAliasGridFit'
    $g.Clear([Drawing.Color]::FromArgb(30, 27, 24))
    $ac = New-Object Drawing.SolidBrush([Drawing.Color]::FromArgb(217, 119, 87))
    $fg = New-Object Drawing.SolidBrush([Drawing.Color]::FromArgb(250, 247, 243))
    $g.FillRectangle($ac, 0, 0, 14, $H)
    $tf = New-Object Drawing.Font($FAM, 84, 'Bold', 'Pixel')
    $y = 200
    foreach ($l in ($Title -split '\|')) { $g.DrawString($l, $tf, $fg, 80, $y); $y += 112 }
    $sf = New-Object Drawing.Font($FAM, 32, 'Bold', 'Pixel')
    $g.FillRectangle($ac, 80, $y + 22, 16, 16)
    $g.DrawString($Sub, $sf, $fg, 110, $y + 12)
    $g.Dispose()
    $bmp.Save($Out, [Drawing.Imaging.ImageFormat]::Png)
    $bmp.Dispose()
}

$rows = Import-Csv -Path $List -Encoding UTF8
foreach ($r in $rows) {
    $out = Join-Path $Dir "$($r.name).png"
    New-Header $r.title $r.sub $out
    Write-Host "$($r.name) : $out"
}
Write-Host "$($rows.Count) 枚できました"

表に行を足せば、その行のぶんだけ増えます。

表計算ソフトで作るなら、保存のときに CSV を選び、文字コードを UTF-8 にしてください。ここを間違えると日本語が化けます。

  • 用途を入れる（header）
  • 拡張子の前に加工の種類は入れない（_new _final を使わない）

名前は、探すときのためにある。

ほかの媒体に回す。書き換えるのは2つ

同じ型を使い回せます。

変えるのは寸法の行だけです。$W と $H の数字を変えれば、その寸法で出ます。正方形にするなら両方を同じ数にする。

ただし2つだけ、ついでに直す場所があります。

  • 文字の大きさ（84 の数字。小さい画像に84pxは大きすぎます）
  • 文字を置き始める高さ（$y = 200 の数字）

目安は、高さが半分になったら文字も半分にする。だいたい収まります。

各媒体の推奨寸法は、媒体ごとの規定を必ず確認してください。 仕様は変わります。この記事に数字を書いても、読んだ時点で古くなっている可能性があります。

私は寸法ごとに型を分けず、同じファイルの $W と $H だけを書き換えて使っています。分けると、色を直したいときに全部を直すはめになるからです。

型は1本のまま、数字だけ動かす。

出す前に、数えて終わらせる

目で見返すのはやめました。

自分で作ったものは、毎回それなりに良く見えてしまいます。だから、合っているか間違っているかしか答えの無い形にして、数えるほうに寄せます。

出したあとに、この1行を実行します。

Add-Type -AssemblyName System.Drawing
Get-ChildItem "$HOME\Desktop\midashi\*.png" | ForEach-Object {
    $i = [Drawing.Image]::FromFile($_.FullName)
    "{0}  {1}x{2}  {3}KB" -f $_.Name, $i.Width, $i.Height, [int]($_.Length / 1KB)

}
