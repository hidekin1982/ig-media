  • 会社のパソコンの Chrome（業務のプロフィール） … 中身: 仕事用のアカウントだけ ／ 使い方: 勤め先の作業だけ

選んだブラウザが、勝手に戻る

ブラウザを操作する仕組みは、一度に1つのブラウザしか受け持てず、つながり直すと、選んでいたほうではなく、もう片方に戻ることがあります。同じパソコンの別のプロフィールなので、タブの番号も似ていて、気づきにくい。

  • 9月29日：1回の作業の中で2回戻った
  • 10月1日：1回戻った（タブが見つからないというエラーで気づいた）
  • 10月2日：選び直しても、毎回すぐに戻った
  • 10月14日：送った直後に、タブごと切れた。仕事用に戻っていた

毎回、選び直しました。

戻ったと分かったら選び直し、書き込む直前にもう一度アカウントを照合してから送っています。10月14日も、送ったあとの確認は、ブラウザを立ち上げ直して選び直し、照合をやり直してからにしました。

仕事用のブラウザでは、どの日も何も実行していません。

9月29日、アカウントの切り替えをやめた

9月23日の時点では、1つのブラウザの中でアカウントを切り替えて使ってよい、という決まりでした。ブラウザが閉じていたら立ち上げてよい、と私が許可したのと同じ日です。

アカウントを切り替えて使うのではなく、作業ごとにブラウザを完全に分ける。

  • 副業の作業は、副業用のブラウザだけで行う
  • 勤め先の作業は、仕事用のブラウザだけで行う
  • 片方が使えない日に、もう片方を予備にしない。作業ごと止めて報告する
  • ブラウザの中で、アカウントを切り替えない

その後、仕事用のブラウザに残っていた副業のログイン（noteや楽天）は、10月2日と4日に私が自分で消しました。

キーホルダーを分けただけでなく、片方の鍵束から、もう片方の家の鍵を外したことになります。

これがいまの形です。

取り合わないために、時間割を決めた

ブラウザを分けても、操作する仕組みのほうは1つしか受け持てません。

副業の作業と勤め先の作業が同じ時刻に動くと、途中で使用中のブラウザを持っていかれて、作業が失敗します。

9月26日と28日の朝には、同じ時刻に動いていた別の作業とブラウザを奪い合い、「このタブは扱える範囲に無い」というエラーで実際に止まっていました。

10月3日に、時間割を決めました。

時間で分けました。

  • 6:00〜9:50 … 副業
  • 10:00〜11:50 … 勤め先
  • 12:00〜12:30 … 副業
  • 13:00〜16:50 … 勤め先
  • 17:00〜翌1:00 … 副業

同じ日に決めたことが、もう2つあります。

  • 定期タスクの名前の先頭に、どちらの作業かが分かる印を付ける（一覧で、取り合いそうな2本がすぐ目に入るように）
  • ブラウザを使わない作業（APIだけで終わるもの、メールやカレンダーの連携）は、時間割の外で動いてかまわない

時間割を決めた翌朝に、私はまた転びます。

10月4日の朝、楽天の投稿を出すタスクが8時4分に起動しました。

アカウントの照合までは済んでいましたが、そこから送信までの間で約2時間止まりました。

送信は10時9分。

同じ朝、6時10分に起動した別のタスクも10時を過ぎてブラウザを使い続けていて、10時22分に動く勤め先の作業と取り合う寸前で、私が止めています。

その日のうちに、手順書に1行を足しました。

  • 書き込む直前に毎回時計を読み、自分の時間帯の外なら送らずに終わる

この1行は、同じ日の夜にさっそく働いています。

19時5分に起動した回が途中で約50分止まり、送る直前の時刻は19時58分で、本文に書いた「あと1時間」が事実と合わなくなっていたので、送らずに捨てました。

時刻を見る相手は、決まりだけでなく、本文の中身でもありました。

決まりどおり「やらない」で終わった回

ここまでの決まりで、何もせずに終わった回を3つ並べます。

  • 10月3日の夜：ブラウザを選び直した直後に、使用中のブラウザが入れ替わった。一度見えたXのタブが、どちらのブラウザのものか確定できず、そのタブには何もしなかった
  • 10月15日の朝：副業用のブラウザを立ち上げて3回試しても、つながったのは仕事用だけ。仕事用を予備にせず、投稿を出さずに終わった
  • 10月15日の夜：一覧に、使わないと決めた自宅のパソコンのブラウザだけが出ていた。それを選ばず、副業用を立ち上げてつなぎ直してから送った

3回とも、外から見れば「何も起きなかった回」です。

同じ10月15日の昼には、別の形の二重送信を出しています。前の晩に出したのと同じ商品を、もう一度紹介してしまったんです。

原因は、前の晩の記録を見ずに、残っていた予備の候補をそのまま出したことでした。

気づいた時点で、続きの返信（商品へのリンク）は送らずに止め、いまは予備を使う前に、直近7日の記録に同じ商品が無いかを必ず見るようにしています。

ブラウザの外の事故です。

書き込む直前の照合、いま使っている指示文の全文

ここまでの決まりを、タスクの手順書に入れている形のまま抜き出しました。

【】を自分の環境に書き換えれば使えますし、ブラウザを1つしか使わない人は、1の「予備にしない」の行だけ残して、1のほかの行は消して構いません。

■ 書き込みの直前に、毎回その場で確かめる（起動したときの確認では足りない）

1. ブラウザ
- 使うのは【この作業用のブラウザ】だけ。一覧の表示名ではなく、固有の番号で選ぶ
- 選んだあと、使用中のブラウザがそれになっているかを確かめる（つながり直すと戻ることがある）
- 一覧に知らない番号しか無いとき、目的のブラウザがつながらないときは、推測で選ばずに作業を止めて報告する
- 別の作業用のブラウザを予備にしない。ブラウザの中でアカウントを切り替えない

2. アカウント
- 【内部の番号】と【画面に出ている名前】の2か所で確かめる
- 食い違ったら止める。ページを開き直し、2回続けて一致したら進む。だめなら作業を止めて報告
- 自分でログアウト・ログイン・切り替えをしない

3. 時刻
- 時計を読み、【この作業の時間帯】の中か確かめる。外なら送らずに「時間外のため未送信」と記録して終わる
- 本文に時刻や残り時間（「あと1時間」など）があるなら、いまの時刻と合っているかも見る。合わなければ出さない

4. 本文
- 入力欄の中身が、決めた文面と一字一句同じか。1字でも違えば出さない
- 送信ボタンが押せないときは、先に文字数を疑う
- 直近7日の記録に、同じもの（同じ商品・同じ記事）を出していないか

■ 送ったあと
- 90秒待ってから公開ページを開き、本文が1つだけ出ているかを見る
- 入力欄が空になったこと、戻ってきた返事（成功・エラー）を、送れた証拠にしない
- エラーやタイムアウトが出ても、打ち直す前に、もう済んでいる件数を数える

■ 終わるとき
- 自分で開いたタブを閉じる。元から開いていたタブは触らない

この形になるまでに、最初の事故から数えて2か月かかり、最後に足した行（直近7日の重複）は、10月15日の昼の事故から生まれたものです。

まだ増えます。

今日これだけやるなら

AIにブラウザを触らせているなら、一覧を開いて、いまつながっているブラウザを全部書き出してみてください。

名前ではなく、中にどのアカウントが入っているかで書くのがこつで、1つのブラウザに2つの用途のアカウントが入っていたら、そこが私の8月17日と同じ場所です。

  • つながっているブラウザを全部書き出す
  • それぞれに入っているアカウントを書く
  • 2つの用途が混ざっているものに印を付ける

1つで足ります。

分けるのに必要なのは、プロフィールをもう1つ作ることだけでした。
